# lkb 品牌资产

`lkb`（Layered Knowledge Base，分层知识库）的 logo、应用图标与字标。全部为纯 SVG：无脚本、无 `foreignObject`、无外链、无渐变、无滤镜，可直接用于 `<img>`、CSS 背景、favicon、PWA manifest 与 Markdown。

## 1. 概念

三层知识层叠构成一个 `L`，右下的负空间里放一个绿点。

- **三层**：顶片、竖笔、基座，对应"一个内核 + 三档 profile"（solo / team / enterprise）——分层是配置与适配器的分层，不是 fork 代码。
- **L**：Layered 的首字母；竖笔与基座包围出的负空间即书页/索引的留白，不放任何装饰。
- **绿点**：检索命中与回答，全标唯一的强调色，位置在 L 负空间的正中（不是随意摆放的点缀，是几何中心）。
- **克制**：只有 4 个图元（3 段层片 + 1 个点）；圆角、缝宽、点径都取自同一套数值，没有第二套风格。

## 3. 几何规范

### mark（32×32 网格，源自所有文件的同一份坐标）

| 项 | 值 |
| --- | --- |
| 活动区 | 24×24，位于 (4,4)–(28,28)；网格内边距 4 |
| 层片厚度 | 7.25（顶片、竖笔）、8（基座） |
| 层缝 | 1.5（顶片与竖笔之间） |
| 外圆角 | 2（= 层片厚度的 27.6%） |
| L 内转角 | 1.2（比外圆角小，保证小尺寸下 L 的内角不被吃掉） |
| 竖笔宽度 | 8 |
| 基座宽度 | 24 |
| 检索点 | 圆心 (20,12)、半径 3.5；直径 7 = 竖笔宽度的 0.875 |
| 检索点位置 | L 负空间中心（x 12–28、y 4–20 的中点） |

三段层片构成 L：**顶片**（独立矩形）、**竖笔**、**基座**。竖笔与基座连成一条 L 形路径共用转角——这是刻意的：层缝只在字母轮廓允许的位置出现，所以层叠感与 L 的可读性同时成立。缩到 24px 以下时 1.5 单位的层缝会被抗锯齿吃掉，形状退化为一个干净的 L，这是设计上的降级路径，不是失真。

## 4. 颜色

| Token | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| `surface` | `#0d0d0f` | `#f5f5f7` | 图标底板、深色画布 |
| `ink` | `#f5f5f7` | `#0d0d0f` | mark、字标 |
| `accent` | `#32d74b` | `#1a7f37` | **仅**检索点 |

对比度（按 WCAG 相对亮度计算）：`ink`/`surface` 17.8:1；`accent`/`surface` 深色 10.1:1、浅色 4.66:1——检索点在两种底色上都达标。

浅色底用 `#1a7f37` 而不是 `#32d74b`：后者在 `#f5f5f7` 上只有 1.76:1，点会糊掉。深浅两版只换颜色，几何一个数值都不改。

## 5. 清空区与最小尺寸

**清空区**：`x` = mark 活动区高度的 1/4（32 网格 = 6；主标 ≈ 9）。四边不得有其他元素（文字、边框、图片、另一枚图标）进入。画布内已预置 6–8 单位内边距，常规摆放无需再加；与文字同行时按 `x` 补足。

| 资产 | 屏幕最小宽 | 印刷最小宽 |
| --- | --- | --- |
| 主标 `logo*.svg` | 96 px（x-height 20 px） | 24 mm |
| 字标 `wordmark.svg` | 72 px | 18 mm |
| 图标 / mark | 16 px | 5 mm |

96px 与 16px 两档已用 Chrome headless 实际渲染核对（16/24/32/48/64/128/256 各档）：16px 时层缝消失，仍能辨认出 L 与检索点。16px 以下不要缩放主标——换用 `icon.svg`。

## 6. 深浅色与使用方式

```html
<!-- 浅色界面 -->
<img src="brand/logo.svg" alt="lkb" width="144" height="54">
<!-- 深色界面 -->
<img src="brand/logo-dark.svg" alt="lkb" width="144" height="54">
<!-- 单色：把 logo-mono.svg 的内容内联进 HTML，颜色跟随父级 color -->
<div style="color:#f5f5f7"><!-- 内联 logo-mono.svg 的 <svg> --></div>
```

- `logo-dark.svg` 是透明背景：放到 `#0d0d0f`、`#1c1c1e`、`#2c2c2e` 上都成立，不要给它再垫一层底板。
- `logo-mono.svg` 用 `currentColor`：**内联**进 HTML 时跟随父级 `color`；用 `<img>` 引用时没有继承上下文，会按黑色渲染。深色底需要单色反白，请用 `logo-dark.svg`，或用 CSS `mask-image` 而不是 `filter: invert()`（invert 会连绿点一起反成粉色）。
- 图标底板只有一种颜色（`#0d0d0f`）。浅色界面同样是深色图标——图标不随系统主题反转，靠底色保证可读性。

## 7. favicon 与应用图标尺寸

| 场景 | 尺寸 | 来源 |
| --- | --- | --- |
| 浏览器标签页 | 32×32（另出 16×16 兜底） | `icon.svg` 导出；现代浏览器也可直接 `<link rel="icon" type="image/svg+xml" href="brand/icon.svg">` |
| PWA manifest | 192×192、512×512 | `icon.svg` |
| PWA maskable | 512×512 | 见下方安全区说明 |
| iOS app | 1024×1024（满幅、不预置圆角，由系统裁切） | `icon.svg`：底板 `rx` 改 0 并铺满画布 |
| apple-touch-icon | 180×180（兼容 120 / 152 / 167） | `icon.svg` |
| macOS app | 16–1024，@1x / @2x | `icon.svg` |
| Android 自适应 | 108dp 前景层 + 背景层 | 见下方安全区说明 |
| 社交卡片 | 1200×630 或 1280×640 | `logo-dark.svg` 居中，左右留白 ≥ 128 px |

**安全区换算**（`icon.svg` 里 mark 占 65.6%，是需要缩小的）：

- maskable / 圆形遮罩：把 mark 收到画布 56%，即 `<g transform="translate(56 56) scale(6)">`，此时最远角距圆心 102px，落在 80% 安全圆（半径 102.4）内。
- Android 自适应前景层（108dp 画布、66dp 安全圆）：mark 收到 43% 才保证任意遮罩不裁切；多数启动器使用圆角方形遮罩，56% 即可。
- 无底板变体（如需要满幅图标）：删掉底板 `<rect>`，把 mark 放大到 `translate(29 29) scale(8.25)`，此时墨迹占画布 77%，四周留白 29px（11%）。

## 8. 错误用法

1. 不要改几何：比例、层缝、圆角、点径、字距都不改；深浅色只换颜色。
2. 不要加渐变、发光、投影、描边、玻璃拟态，不要给 mark 加外框或圆角底（图标底板除外）。
3. 不要用蓝紫渐变或第二种强调色；绿点永远是唯一彩色元素，且只表示检索/回答。
4. 不要把绿点放大到与层片同宽、挪到 L 之外，或用于其他元素（按钮、状态灯沿用同一 token 可以，但不要改 logo 里的点）。
5. 不要改成大写 `LKB`、不要加字距、不要在 mark 上叠字、不要把字标塞进 L 的负空间。
6. 不要非等比缩放（压扁/拉伸）、旋转、倾斜、镜像。
7. 不要在 mark 上做"多层不同颜色"的变体——三层只有 ink 一种颜色。
8. 不要在低对比背景（中灰、照片、杂乱图案）上直接放 logo；用 `icon.svg` 的底板或先垫 `#0d0d0f` / `#f5f5f7`。
9. 不要用 `filter: invert()` / `hue-rotate()` 反色，绿点会偏色；单色需求用 `logo-mono.svg`。
10. 不要低于最小尺寸硬压：96px 以下用图标，16px 以下不要渲染主标。

## 9. 维护与放置建议

**现阶段（单一产品、mark 仍在演进）：品牌资产随主仓维护。** `brand/` 与代码、ADR 同仓，改动走同一个 PR 评审；这样"改几何"和"改产品"永远在同一份历史里，不会出现仓库间漂移。需要导出物（PNG/ICO/社交图）时按上表尺寸从 SVG 生成，源文件始终只有这 5 个。

**如果组织有独立的 brand / design 仓：只做镜像，不做第二份源。** 具体做法：

- 主仓 `brand/` 保持为唯一事实源（source of truth），独立仓只放只读镜像 + 导出物（PNG、ICO、演示模板、社交图）；
- 独立仓 README 首行指回主仓路径，并写明"禁止在此直接编辑 SVG"；
- 用 CI 定时同步或 `git subtree`，单向流动；不要双向同步，也不要两边各存一份可编辑副本；
- 对外引用（文档站、README、CDN）固定到 tag 或 commit 的 raw URL，不要指向 `main` 分支。

**未来若多个产品共用同一个 mark**：那时才把源迁到组织 brand 仓，产品仓 `brand/` 退化为"指路 + 本地导出物"，主仓不再保存可编辑源。判据是共享方数量与发布节奏：只有一个产品消费时，独立仓只会增加同步成本。

## 10. 校验

本目录的 SVG 均已校验：XML well-formed、`viewBox` 明确、无 `<script>` / `foreignObject` / `href` / `url()` / 渐变 / 滤镜 / `<style>` / 外链字体；并在 Chrome headless 中按 16/24/32/48/64/128/256 px 渲染核对过深浅两色与单色版本。
