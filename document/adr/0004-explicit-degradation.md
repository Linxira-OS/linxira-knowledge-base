# ADR 0004：可选能力缺失时显式降级

- **状态**：Accepted
- **日期**：2026-11-08

## 背景

能力按档位分布：LLM、向量模型、图谱索引、多模态解析、身份服务在不同 profile 下可用性不同，且即使在 enterprise 也会运行期故障。如果可用性差异被静默吸收，会产生三类失真：

- **用户失真**：用户看到一段没有引用、没有生成式组织的结果，以为系统"就是这样"，而不是"某能力当前不可用"。
- **评测失真**：回归基线混合了不同能力组合的结果，指标变化无法归因；也无法回答"降级时质量损失多少"。
- **Agent 失真**：Agent 消费者无法据此重试、切换策略或提示人类，只能把降级结果当作完整答案继续推理。

solo 档本身就是"能力受限的常态"：没有 LLM 时必须可用，这是设计前提而非异常。

## 决策

**每个可选能力都有明确的可用性判定与降级结果；不可用时在响应中返回 `degraded[]`，基础能力继续服务；禁止静默回退。**

- `degraded[]` 是响应契约的一部分（见 ADR 0005），每项标明能力标识与不可用原因分类，不静默省略。
- 降级路径与被降级路径在契约上可区分：回答需要标明是抽取式还是生成式，引用缺失必须显式为空而不是编造。
- 启动时探测与运行期失败都要落到同一汇报机制；运行期失败不允许仅写日志而不进入 `degraded[]`。
- **安全能力不降级放行**：身份与 ACL 缺失时 fail-closed（拒绝请求），返回错误而不是 `degraded[]` 后继续返回内容。治理过滤不可被"降级"为 allow-all（ADR 0002）。
- 降级不得改变检索管线的顺序与截断语义：融合、TopN 打分、治理过滤仍在同一位置执行。

## 备选方案与为何不选

| 方案 | 否决理由 |
| --- | --- |
| 静默回退到关键词检索 / 抽取式回答 | 用户、评测、Agent 三方都无法区分质量差异；回归指标失去意义，故障不可观测 |
| 任一能力缺失则整体失败 | 违反"个人可用"前提：solo 无 LLM 是常态，整体失败等于 solo 不可用 |
| 只在日志与监控里告警，响应不带降级信息 | Agent 与前端无法据此决策；人类用户也无法判断答案是否可信 |
| 用统一的 "partial" 布尔代替能力清单 | 无法归因到具体能力，也无法统计各能力的降级频率与质量损失 |
| 身份服务不可用时临时放开权限 | 越权泄漏；且会让"不可用"成为绕过治理的路径 |

## 后果

**正面**

- 可观测：降级率按能力分解，故障与容量问题可以直接定位。
- 可评测：全能力基线与降级基线分开记录，质量损失成为可量化指标。
- Agent 可行动：消费方可根据 `degraded[]` 决定重试、改用其他通道或向人类升级。

**负面**

- 契约与调用点成本：每个返回路径都要携带 `degraded[]`，前端与 Agent 都要处理它。
- 能力与原因需要分类枚举，枚举本身是版本化契约，新增能力需要更新消费者。
- 探测本身可能误判：启动探测通过但首次真实调用失败，需要运行期捕获并合并汇报。

**需要监控的信号**

- `degraded[]` 非空率，按能力与档位分解。
- 各能力降级期间的答案质量指标，与全能力基线的差值。
- 静默回退回归用例数（应为 0）；任何"未声明就换实现"的路径都算缺陷。
- 安全能力不可用导致的拒绝次数，以及是否有请求在治理过滤缺失时仍返回内容（应为 0）。
