# ADR 0005：人类与 Agent 共用同一 Answer 契约

- **状态**：Accepted
- **日期**：2026-11-08

## 背景

知识库有两个消费面：人类界面（CLI、本地 Web）与 Agent（REST、MCP）。若各自定义返回结构，会立刻出现分叉：

- 三套引用格式，其中只有一套支持回跳原文（ADR 0003）；
- 三套降级语义，其中有的把缺失能力吸收进"无结果"（ADR 0004）；
- 评测只覆盖其中一条通道，其余通道的质量无人验证；
- 更严重的是，接口层为了"顺手"，直接访问索引或自行做过滤，绕开治理与融合路径。

同时，v1 的几个有效取舍（RRF 融合、打分模型只作用于 TopN、召回期 ACL）只有在单一检索路径上才成立；多路径意味着这些语义要在多处复制。

## 决策

**定义一个 Answer 契约，人类与 Agent 共用；REST / MCP / CLI 共同调用同一检索内核。**

- **同一内核**：三条通道都只调用内核的检索入口。接口层只做传输与呈现适配，不持有索引句柄，不自行召回、过滤或重排。
- **契约字段族**（具体字段以 architecture.md 的契约为准）：
  - 回答正文，并标明是抽取式还是生成式；
  - 引用集合，每项由 doc_id 与源文件位置构成，必须可回跳；
  - `degraded[]`，标明本次回答缺失的可选能力（ADR 0004）；
  - 治理与可解释信息：本次检索生效的空间/租户上下文与版本标识；
  - 请求回显：原始问题与生效的检索参数，便于复现与评测。
- **契约不假设生成式能力**：solo 无 LLM 时，正文为抽取式，引用与 `degraded[]` 仍然完整。契约的最低形态由最低档决定（ADR 0001）。
- **管线语义统一**：召回通道组合（单通道或混合）、RRF 融合（仅多通道时启用）、TopN 打分、召回期治理过滤在三条通道上是同一份实现、同一顺序。
- 引用不可回跳时不得返回该引用：宁可在 `degraded[]` 中声明，也不返回无法核对的来源。

## 备选方案与为何不选

| 方案 | 否决理由 |
| --- | --- |
| CLI / Web 走"简化路径"，Agent 走完整路径 | 两条检索语义、两套引用质量；人类与 Agent 对同一问题得到不同答案，评测无法比较 |
| 每个接口自定义 DTO，由内核返回内部对象再各自映射 | 映射层会逐渐加入业务逻辑（过滤、截断、降级吞并），契约分叉不可逆 |
| 展示层使用"优化版"契约（摘要化、隐藏引用） | 引用与降级信息在展示层丢失，用户无法核对；Agent 与人类观察到的系统不一致 |
| 只定义 REST，CLI 与 MCP 复用其 HTTP 客户端 | 看似统一，但通道仍多一层网络与序列化，且容易在客户端做后处理；不如直接共享内核调用 |

## 后果

**正面**

- 一次评测覆盖全部通道：指标、引用可回跳率、降级率可直接对比。
- 引用与降级语义只有一处定义，新增通道的边际成本低。
- Agent 与人类看到同一份证据，人机协作时可互相引用同一 doc_id 与位置。

**负面**

- 契约是最慢的变更点，字段语义变更需要版本化并同步所有消费者。
- 契约受最低档能力约束：不能要求"必然有生成式正文"或"必然有向量召回"。
- 流式输出与"引用在全文确定后才完整"存在张力，需要在契约层明确引用的就绪时机，前端不能假定首屏即有引用。
- CLI 的呈现自由度受限，必须承载完整字段而非只打印一段文本。

**需要监控的信号**

- 通道间 Answer 字段一致性测试的失败数（目标为 0）。
- 非内核检索路径的调用数：接口层直接访问索引、自行过滤的次数（目标为 0）。
- 引用不可回跳率（目标为 0）；被返回但无法定位源文件的引用数。
- 契约版本分布：仍在使用旧版本的消费者数量与存续时长。
- 同一问题跨三通道的指标差异，超出噪声范围即视为契约实现分叉。
