# 常见误用

## 权限相关

把 ACL 过滤放在取回结果之后，会让无权限文档占用 TopN；正确做法是召回 SQL 内过滤，再做一次进程内校验。ACL 解析失败时放行也是误用，必须拒绝。

## 能力相关

以为 hybrid 默认开启是误用：只有显式配置 embedding provider 才会走向量通道，否则 auto 选 bm25，且不写 `dense_not_enabled`；只有显式选择 hybrid 时，未启用向量才写该降级。把 `not_enabled` 写成 `unavailable` 会污染降级率。

以为 PostgreSQL 也用 BM25 同样错误：它用 `ts_rank_cd` 与 `websearch_to_tsquery`，分数尺度不同。

## 身份与命令

当前入口只有 `lkb import`、`lkb search`、`lkb ask`、`lkb serve` 等，子命令以 `lkb --help` 为准；不要沿用旧版本的命令形态。把密钥写进 `lkb.toml` 也不允许，只能用 `api_key_env`。

## 引用锚点

把 `chunk_id` 当作外部长期引用是误用：它包含分块器版本，分块策略变化就会变。长期引用应使用 `doc_id` 加逻辑路径与行号；`chunk_id` 只适合单次索引代次内定位。
