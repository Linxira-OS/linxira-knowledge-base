# 认证与会话

## 两种主体

浏览器走会话：登录后服务端只保存 session id 的 SHA-256，cookie 为 HttpOnly、SameSite=Lax，非回环地址自动加 Secure。Agent 与 CLI 走 `Authorization: Bearer`，数据库只保存 token 的 SHA-256、scope、过期时间与吊销时间。

token 的 scope 为 read、write、admin；原始 token 只在创建时显示一次。过期、吊销、跨租户或用户被禁用都返回 401。

## CSRF

写请求要求 CSRF 校验：页面下发 `lkb_csrf` cookie，表单带上同值字段。`auth.csrf = true` 时缺失或不匹配返回 403。API 的 GET search 与 POST ask 在 session 模式下要求 Bearer，不接受仅凭 cookie。

## 启动约束

`auth.mode = "none"` 只允许绑定回环地址；绑定 0.0.0.0 等非回环地址时进程拒绝启动。solo 默认 127.0.0.1 免认证；team 与 enterprise 必须启用会话并配合 PostgreSQL。

登录失败有频率限制，同一来源与用户名连续失败会暂时锁定，避免在线爆破。
