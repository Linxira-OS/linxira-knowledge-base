# 分层架构

## 一个内核，三档配置

LKB 只有一个 Rust 内核：`src/lib.rs` 暴露配置、治理、存储、摄入、检索、回答、provider、Web 与 CLI 模块，`src/main.rs` 只调用库入口。solo、team、enterprise 三档 profile 共享同一套摄入、检索、融合、打分与 Answer 契约。

档位差异只允许出现在配置与适配器装配层：solo 用 SQLite 单文件，team 与 enterprise 用 PostgreSQL；身份从免认证到本地会话再到组织身份。领域逻辑中不得出现按 profile 分支的代码。

## 分层数据流

请求先经过身份与策略层，再进入查询理解与召回；召回结果经融合与可选重排，最后进入回答合成与引用装配。

L1 接入与身份、L2 查询理解、L3 多路召回、L4 融合与重排、L5 生成与呈现，L6/L7 是知识底座与存储，L8 是运营与评测。CLI、本地 Web 与 HTTP API 都调用同一个检索入口，接口层只做传输与呈现适配。

## solo 的默认形态

solo 使用 SQLite 单文件，关键词通道为 FTS5 BM25；不配置外部模型时不发网络请求，回答走抽取式。治理字段照常写入，ACL 取 allow-all，但过滤代码路径与高档位相同。

规模目标与逐项能力差异见 `document/tier-matrix.md`；本目录只描述使用与验收口径。
