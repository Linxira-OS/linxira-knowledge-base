# 文档身份与重建

## doc_id 如何派生

先规范化逻辑路径：反斜杠转正斜杠，去掉空组件与 `.`，拒绝绝对路径、盘符和 `..`，ASCII 字母转小写。然后计算 `doc_id = hex(sha256(规范化相对路径 + "\0" + 内容哈希))`，取前 16 字节，得到 32 个小写十六进制字符。

路径提供逻辑归属，内容哈希提供版本区分。因此同一份内容放在不同路径下不会互相覆盖，同一路径下的不同内容也会得到不同身份。

## 重建是否稳定

文件是事实源，SQLite 是派生缓存。删除数据库后对同一目录重新 `lkb import`，doc_id 集合应完全一致。重复导入时，已存在的 doc_id 或未变化的内容会被跳过，报告里分别计入 skipped 及原因。

## 版本替代

内容变化会生成新的 doc_id。旧记录 `status` 变为 superseded，`superseded_by` 指向新 id，并把 `valid_to` 设为替代时间。当前时刻查询不会再看到旧版本；历史 `as_of` 查询仍可复现当时版本。

## chunk_id 的边界

`chunk_id` 由租户、doc_id、序号、分块器版本与分块内容哈希派生，前缀为 `chk_`。分块策略变化会改变 chunk_id，因此长期引用应使用 doc_id 加逻辑路径与行号，而不是 chunk_id。
