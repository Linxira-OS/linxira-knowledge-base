# 配置与密钥

## 配置来源

默认读取工作目录的 `lkb.toml`，可用 `--config` 指定其他路径。环境变量覆盖同名配置：例如 `LKB_PROFILE`、`LKB_BIND`、`LKB_AUTH_MODE`、`LKB_STORAGE_BACKEND`、`LKB_SQLITE_PATH`、`LKB_DEFAULT_SPACE`。

solo 档在归一化时强制 `tenant_id = t_local`、`default_space = s_default`。solo 只能配 SQLite，team 与 enterprise 只能配 PostgreSQL，非法组合在启动前报错。

## 模型端点

LLM、embedding、judge 三段配置字段相同：`provider`、`base_url`、`model`、`api_key_env`、`timeout_ms`、`max_retries`。`provider = "none"` 表示关闭；非 none 时 base_url 与 model 必填。

## 密钥

密钥只从 `api_key_env` 指定的环境变量读取，不写入配置文件，也不写入日志。变量缺失时该能力构造失败并进入 `degraded[]`，不会联网重试其他来源。

`lkb config check` 打印生效配置，对数据库 URL 打码，对密钥只显示 set / missing / not configured，不显示原文。模型价格与版本不在示例中写死，统一见 knowledge-freshness 台账。
