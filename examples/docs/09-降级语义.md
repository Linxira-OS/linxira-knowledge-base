# 降级语义

## 降级条目

`degraded[]` 的每项包含 `code`、`category`、`capability`、`expected_level`、`actual_level`、`reason`、`impact`、`fallback`。排序优先级为 security > evidence > quality > performance。

## not_enabled 与 unavailable

`not_enabled` 表示该能力本来就没有启用，例如显式选择 hybrid 但未配置 embedding 时的 `dense_not_enabled`。`unavailable` 或 `timeout` 表示已启用但本次失败，例如 `embedding_unavailable`、`decision_unavailable`、`llm_unavailable`。把两者混用会让降级率指标失去意义。

只有“请求需要但不可用”才应上报：solo 没有配置 judge 时，普通查询不写 `decision_unavailable`。

## 没有 LLM 时回答如何生成，引用是什么

没有 LLM 时走抽取式回答：取最高分证据的原文片段，附 `doc_id`、路径、行号与 `quote` 引用，不生成原文没有的句子。引用必须能回跳到源文件位置；无法定位的引用不返回。回答模式标记为 `extractive`，`degraded[]` 不会因为“本来就没有配置 LLM”而报错。

## 安全能力例外

身份与 ACL 不参与降级放行。主体缺失、租户不匹配、ACL 解析失败时请求被拒绝或候选被丢弃，不允许回退成 allow-all。`acl_second_check_dropped` 属于 security，表示候选被剔除而不是放宽。

## 全部失败时

所有通道都没有证据时，回答为 null、citations 为空、置信度为 low，`degraded[]` 列出原因，这是正常业务响应。只有认证失败、输入非法或存储不可用才返回 4xx/5xx。
